Backup failure triage with Jev

autorestic + restic lab. When a backup fails, its output goes to Jev and a typed decision comes back.

How it works

Happy path
1 · wrapper
backup.sh <location>
Runs autorestic under a timeout, captures the full output to logs/, owns the exit code.
2 · orchestrator
autorestic
Reads .autorestic.yml, maps the location to its backends, runs hooks.
3 · engine
restic backup
Deduplicated, encrypted snapshot. Retries a dead backend on its own for up to 15 min.
4 · storage
local · rest-server · rest-server (5 MB)
Three repositories, one per location.
Failure path (exit code ≠ 0)
5 · state
log tail → JSON
Last 80 lines of restic output, location, exit code, timed_out flag.
6 · decision model
Jev, 4 questions in one call
Typed answers with probabilities. No prose, ~0.5 s, ~700 tokens.
7 · policy
deterministic mapping
locked → unlock & retry · backend down → retry later · else alert by urgency.
8 · action
retry · unlock · alert
Outcome and full decision appended to results.jsonl and alerts.log.
cause · choice among 8 root causes, each described in plain language
transient · boolean, will it resolve itself within minutes?
needs_human · boolean, is a person required?
urgency · score over 4 levels: low → medium → high → critical
