# autorestic + restic + Jev lab

POC 1: **automatic backup failure triage** with [Jev](https://vercel.com/ai-gateway/models/jev)
(TypeSafe AI's typed-decision model, through Vercel AI Gateway).

When `autorestic backup` fails, `backup.sh` hands the output to Jev, which returns the cause,
whether it is transient, whether a human is needed and the urgency, all with probabilities.
An explicit policy turns that into an action: unlock and retry, retry later, alert, or alert
as critical.

Nothing is installed on the system: static binaries in `bin/`, backends in Docker.

## Quick start on a fresh machine

Requirements: Docker with the compose plugin, Node.js 22+, `jq`, `curl`, `bzip2`. Linux or macOS
(on macOS also `brew install coreutils` for `timeout`; on Windows use WSL). Nothing is installed
system-wide: restic and autorestic are downloaded into `bin/`, the backends run in Docker.

```bash
git clone <this repo> autorestic-lab && cd autorestic-lab
cp .env.example .env            # then put your AI_GATEWAY_API_KEY in it
./setup.sh                      # binaries, npm deps, repo keys, sample data, Docker backends, repo init
./run-all.sh                    # the 7 failure scenarios, ~3 minutes
npm run demo                    # UI at http://127.0.0.1:8600
docker compose down             # stop the backends when done
```

`setup.sh` is idempotent: it only creates what is missing, so it is safe to re-run.

### Configuration and secrets

| File | Committed | Purpose |
|---|---|---|
| `.env.example` | yes | Template for `.env` |
| `.env` | no | `AI_GATEWAY_API_KEY` (Vercel AI Gateway) and optional `DEMO_PORT`. Loaded by `backup.sh`, the scenarios and the demo server. |
| `.autorestic.env` | no | Repository keys, generated by `setup.sh` as `AUTORESTIC_<BACKEND>_RESTIC_PASSWORD`. autorestic reads it automatically. Losing it means losing the backups. |
| `.autorestic.yml` | yes | Backends and locations. Contains no secrets; `requireKey: true` stops autorestic from generating keys and rewriting the file. |

The AI Gateway key must belong to a Vercel team with a card on file, otherwise every request
fails with `403 customer_verification_required`. Jev is free on the gateway until 2026-09-25;
after that the list price is $0.042 per 1M input tokens, about 700 tokens per triage.

### Ports

The backends listen on `127.0.0.1:8500` (rest-server) and `127.0.0.1:8501` (rest-server with a
5 MB quota). They are hard-coded in `docker-compose.yml` and `.autorestic.yml`; change both if
they clash with something on your machine. The demo UI uses `DEMO_PORT` (default 8600).

## Demo UI

```bash
npm run demo                  # http://127.0.0.1:8600  (reads AI_GATEWAY_API_KEY from .env)
```

A single page served by `demo/server.mjs` (no dependencies) that explains the pipeline, runs any
scenario or a normal backup with live output, and reads `logs/` to show the results table,
Jev's full answer per run (probability bars for cause and urgency), the alerts and the hook log.
The server only listens on localhost and only executes the scripts of this lab.

## Layout

| Path | What it is |
|---|---|
| `.autorestic.yml` | 3 backends (`local`, `remote`, `quota`) and 3 locations over `data/` |
| `setup.sh` | Bootstrap for a fresh machine (see Quick start) |
| `backup.sh` | Wrapper: `autorestic backup` with timeout, Jev triage and action |
| `jev/triage.mjs` | Jev call: questions `cause` (choice), `transient` and `needs_human` (boolean), `urgency` (score), plus the policy |
| `scenarios/*.sh` | Reproducible breakages: backend down, foreign lock, wrong key, disk full, permissions, damaged repo, invalid config |
| `run-all.sh` | Runs every scenario and compares the expected cause with Jev's |
| `demo/` | `server.mjs` (JSON + SSE API) and `index.html` (the demo page) |
| `logs/` | Output of every backup, `results.jsonl`, `alerts.log`, `hooks.log` |
